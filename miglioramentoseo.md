- Gemona del Friuli

- Venzone
- Tarcento

La priorità assoluta è:

1. Gemona del Friuli
2. comuni immediatamente circostanti
3. Tolmezzo
4. Udine

NON voglio una semplice duplicazione delle attuali pagine `/comuni`.

Voglio creare una serie di LANDING PAGE SEO LOCALI DI ALTISSIMA QUALITÀ, realmente differenti tra loro, utili per un potenziale cliente e progettate per competere con i risultati già presenti su Google.

# FASE 1 — ANALISI DEL PROGETTO ESISTENTE

Prima di modificare qualsiasi codice:

1. Analizza completamente la struttura del progetto.
2. Individua:
   - routing;
   - struttura `/comuni`;
   - JSON dei comuni italiani;
   - script che genera le pagine;
   - metadata;
   - sitemap;
   - robots.txt;
   - canonical;
   - schema.org / JSON-LD;
   - componenti riutilizzabili;
   - layout;
   - sistema di linking interno;
   - eventuale gestione `noindex`;
   - immagini;
   - performance;
   - dati strutturati.
3. NON modificare ancora nulla.
4. Produci prima un'analisi tecnica interna del sistema esistente.

Devi capire soprattutto come possiamo mantenere l'attuale generazione dinamica tramite JSON senza distruggerla.

# FASE 6 — SEO ON-PAGE

Ogni pagina deve avere metadata specifici.

NON utilizzare semplicemente:

"Siti web a {comune} | Jaderweb"

per tutte.

Crea title naturali e orientati al search intent.

Esempi concettuali:

"Sviluppatore Web a Gemona del Friuli | Siti ed E-commerce"

"Realizzazione Siti Web per Aziende a Buja | Jaderweb"

"Siti Web ed E-commerce a San Daniele del Friuli"

Ma scegli il title finale sulla base della ricerca keyword.

Per ogni landing crea:

- title;
- meta description;
- canonical;
- H1 unico;
- H2/H3 semanticamente coerenti;
- Open Graph;
- eventuale Twitter metadata;
- breadcrumb;
- schema.org appropriato.

# FASE 10 — CONTENUTO

Il copy deve sembrare scritto da un professionista locale, non generato automaticamente.

Evita frasi generiche come:

"Se cerchi un sito web professionale a X sei nel posto giusto."

Evita inoltre:

- keyword stuffing;
- ripetizione ossessiva del comune;
- testi inutilmente lunghi;
- paragrafi riempitivi;
- contenuti identici;
- promesse assolute;
- "primo su Google";
- "garantisco il primo posto".

Il contenuto deve rispondere alle domande reali del cliente.

Per esempio:

"Quanto costa realizzare un sito web a Gemona?"

"Quanto tempo serve?"

"Posso aggiornare il sito autonomamente?"

"Realizzi e-commerce?"

"Puoi occuparsi anche della manutenzione?"

"Segui anche la SEO?"

"Posso affidarti un sito già esistente?"

Le FAQ devono essere personalizzate per ogni zona quando possibile.

# FASE 14 — INDEXING

Questa parte è FONDAMENTALE.

NON eliminare automaticamente le 7.904 pagine `/comuni`.

Analizza prima:

- quali sono indicizzabili;
- quali vengono inserite nella sitemap;
- quali sono realmente indicizzate;
- quali hanno contenuto duplicato/simile;
- quali ricevono internal link;
- quali hanno valore SEO.

Le nuove landing devono essere chiaramente più importanti delle pagine comunali generiche.

Valuta una strategia del tipo:

LANDING STRATEGICHE
↓
index, sitemap
↓
forte internal linking

PAGINE COMUNI GENERICHE
↓
eventuale noindex / riduzione sitemap / mantenimento tecnico

MA NON applicare `noindex` o cancellazioni massive senza prima analizzare il sistema.
